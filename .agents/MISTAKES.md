# 실수 목록 (다시 하지 말 것)

코딩·수집·차트 작업 전에 이 파일을 읽는다. 같은 실수를 반복하면 여기 항목을 어긴 것이다.

## 차트·순위

-1. **표는 6개월인데 전장 맵은 3개월 / 발주처 공란**
   - 잘못: 차트 팝업이 저장소를 다시 읽어 예전 스냅샷을 씀. C++ jsonl에 발주처를 안 넣음.
   - 규칙: 차트 팝업은 본문과 같은 `CurrentParticipants`를 복사한다. 수집 jsonl에 `ordering_agency`를 넣는다.

0. **6개월 설정인데 차트가 3개월만 보임**
   - 잘못: 2~4월 C++ 수집값이 `bidprcrt`(85~88, 예가/기초대비투찰률)인데 전장 맵은 99~101만 그린다. 6~8월만 99.xxxx라 3개월처럼 보인다.
   - 규칙: 차트 X는 기초대비사정률 = 투찰률 / 낙찰하한율 * 100. 86.x를 adjust_rate에 넣지 않는다.

0b. **전장 맵 1위가 축 중앙(100%)에만 몰림 / 실제 1위가 아님**
   - 잘못: OpenAPI `bidprcrt`(예가대비투찰률 86.x) ÷ 낙찰하한율 → 100.014를 `adjust_rate`에 넣고 `chip.rank == 1` 금색을 그대로 그림. 창녕-고암(R26BK01673928-000) 실제 1위는 춘추 99.78004(아이건설·기초예가 공식)이지 100.014가 아니다. `ToChartAdjustRate`는 99–101이면 원값을 유지해서 이 값을 고치지 못한다.
   - 규칙: 전장 맵 1위 좌표는 기초대비사정률(아이건설 99.xxxx / `ComputeBaseAdjustRate(투찰금액, 기초예가, 하한)`). 예가대비÷하한으로 만든 100.00±0.15 군집을 1위 위치로 쓰지 않는다. 금색은 그 좌표의 낙찰 업체에만. 나라장터에 이미 있는 99.xxxx는 덮지 않는다. 아이건설넷은 나라장터에 사정률이 없거나(86.x/96.x/100.00 군집) 업체가 없을 때만 쓴다.

0c. **99.90–100.20 실제 1위를 가짜 100군집으로 지움**
   - 잘못: `LooksLikeOpenApiHundred`(하한율 있는 99.90–100.20 칩)를 1위 금색/토글/표 낙찰에 그대로 씀. 칩이 99.1–100.9로 퍼진 공고의 진짜 1위(99.95, 100.04 등, 2위가 바로 위)가 구멍처럼 사라짐.
   - 규칙: 가짜 100은 `NoticeHasLowerLimitAwardCluster`만. 1위가 그 구간에 있어도 다른 칩이 99–101에 퍼져 있으면 `IsMappedRank1`. 칩 봉우리(100.29)와 1위 위치는 다를 수 있다.

1. **표 순위 ≠ 차트 칩 수**
   - 잘못: DB/엑셀에 남은 원본 `Rank`(62위, 40위)를 그대로 표에 씀. 전장 맵은 99–101 창의 고유 업체만 칩으로 그림.
   - 규칙: 칩 수 = 창 안 고유 업체 수. 동국 순위 = 그 칩들 안에서의 순위. 문구에 `N개사`를 넣어 칩 수와 같게 한다. `ScatterChartRules` / C++ `BuildScatterNotice`만 쓴다.

2. **동국이 안 들어간 공고에 칩**
   - 잘못: `CurrentParticipants`에 스냅샷 전체를 넣어 전장 맵이 전 시장을 그림.
   - 규칙: 차트는 `ApplyChartRules` 이후만. 동국 참여 공고의 공동입찰 업체는 남긴다.

3. **기간 설정을 차트에 안 넣음**
   - 잘못: 좌측 하단은 최근 6개월인데 전장 맵이 3개월(또는 캐시된 전체)만 그림.
   - 규칙: `NativeBidChartControl`은 `StartDate`/`EndDate`를 바인딩하고 `ScatterChartRules.InPeriod`로 자른다. 1개월·3개월·6개월·1년·전체기간 모두 같은 경로.

4. **업체 필터 후 KeepDongguk을 다시 걸어 차트 공백**
   - 잘못: 한울만 남긴 뒤에 동국 게이트를 또 적용해 공고가 사라짐.
   - 규칙: 공고 우주를 먼저 자르고, 그다음 업체로 칩만 줄인다.

34. **C++ 글자가 C#보다 흐릿하고 첫 화면 스파크라인이 매 페인트마다 99점을 그림**
   - 잘못: DirectWrite grayscale + contrast 0. 헤로에 이중 꺾은선. 툴바가 오른쪽 끝에 붙음.
   - 규칙: ClearType NATURAL_SYMMETRIC. 첫 화면은 KPI 3칸+표+업데이트. 툴바는 폭의 20% 왼쪽.

33. **업데이트 버튼이 먹통처럼 보이고 12개월을 다시 받음**
   - 잘못: 진행 문구가 회색 푸터에만 있어 안 보임. 이미 sqlite에 있는 달을 OpenAPI에 다시 친다.
   - 규칙: 노란 상태 줄 + 버튼 `수집 중`. `PlanMissingCollect`는 저장 최신 개찰 다음날~오늘만. 빈 DB만 1년 창.

32. **맵 Y를 최신 위로 뒤집으면 원래 공고가 사라지고 위아래가 반대가 됨**
   - 잘못: 최신이 안 보인다고 행 순서를 뒤집음. 맵은 C#처럼 오래된 공고가 위, 최신이 아래. 뒤집으면 6월이 아래로 가고 8월만 위에 남는다.
   - 규칙: `SortNoticeKeysOldestFirst`. `ShowLatestView`는 맨 아래(최신)로 스크롤. 금테는 칩 안쪽. 최신 행 Y라벨을 plot 바닥에 잘리지 않게 한다.

31. **동국 통통 애니메이션이 50ms마다 맵을 다시 그려 렉이 나고 옆 칩 글자를 덮음**
   - 잘못: `kBounceTimer` 50ms + scale 1.12 overlay. 정적 레이어의 문화 라벨이 가려지고, 업체 체크 시 dodge 칸은 글자를 생략함. 맵 초기화는 줌만 리셋.
   - 규칙: 동국 bounce off. 칩 글자는 칸 안 클립으로 남긴다. 맵 초기화는 업체 체크도 전부 해제(`ResetMapFilters`).

30. **전장맵 탭을 붙인 뒤 공고날짜가 전장맵 버튼을 뚫고, 같은 칸 칩 글자(재/륜)가 겹침**
   - 잘못: 축 제목을 plot.y-16에 그려 탭과 겹침. 같은 0.01칸 칩은 1px만 밀어 글자가 포개짐. 맵을 3D로 올려서 풀려고 함.
   - 규칙: Y라벨은 탭 아래·플롯 안에서만. 겹친 칩은 칸 안 격자(dodge). 작은 칸은 글자를 생략하고 호버에 2글자명을 넣는다. 전장 맵은 3D가 아니다.

29. **히스토그램이 전체 봉우리(353)로 Y축을 잡고 업체 막대를 따로 키움 / 1위 토글이 맵만 자름**
   - 잘못: 전체와 선택 업체를 Z로 겹쳐 그리고, 업체 막대는 company_max로 따로 스케일해서 한 업체 20건이 353처럼 보임. 1위 버튼은 전장 맵 칩만 숨김.
   - 규칙: 보이는 시리즈와 Y축은 같은 max. 업체 체크 시 전체 막대를 빼고 칸 안에서 나란히(cluster). 1위는 `IsMappedRank1` 칩만 분통.

## 수집

4. **업데이트 = 마스터 엑셀만 재로딩 / 수집이 3개월만 / 수집을 파이썬으로 함**
   - 잘못: 파이썬 파이프라인이 타임아웃·3개월 데이터만 남림. 수집은 C++이어야 하는데 파이썬을 돌림.
   - 규칙: 나라장터 낙찰 수집 엔트리는 `nara_award_collect` (C++). 조회는 3개월 창으로 나눈다. 파이썬 collect는 쓰지 않는다.

20. **지역을 목록 빈칸이면 전부 전국으로 넣음**
   - 잘못: `rgnLmtBidLocplcJdgmBssNm`이 비면 `전국`. sqlite 185공고 중 183이 전국. 파이썬은 `getBidPblancListInfoPrtcptPsblRgn`으로 참가가능지역을 읽는다.
   - 규칙: 토큰은 `전국`|`경북`만. `경상북도`/`대구,경북` → `경북`. 목록이 비면 참가가능지역 API. 전북 등은 버린다.

19. **나라장터 1위를 예가대비÷하한으로 100.00에 붙임**
   - 잘못: `bidprcrt`÷`sucsfbidLwltRate` 또는 예산(asignBdgtAmt)을 기초예가로 써서 분홍선이 100에 수평.
   - 규칙: 기초대비사정률 = `ComputeBaseAdjustRate(투찰금액, bssamt, 하한)`. 기초예가는 PreparPcDetail `bssamt`만. 86.x를 100으로 바꾸지 않는다.

18. **차트 칩 165건 vs 표 86건**
   - 잘못: 히어로 `전국 · 공고 N건`에 persist(6개사+) 시장 공고 수를 넣고, 표는 동국 99–101만 셈.
   - 규칙: 칩·추세·표는 같은 `g_table` / `BuildAwardNoticeRows` 건수다.

17. **업데이트 후 jsonl을 sqlite에 안 넣음 / 경로를 A:\\c에 고정**
   - 잘못: `nara_award_collect`만 돌리고 `LoadParticipants`로 예전 DB를 다시 읽음. db/jsonl/env가 `A:\c\...` 고정이라 다른 PC에서 빈 화면이 됨.
   - 규칙: 수집 jsonl을 앱 폴더 `nara-dashboard.db`에 공고 단위로 병합한 뒤 표·차트를 다시 읽는다. sqlite는 포터블 누적 파일이다. 파이썬 merge 스크립트에 의존하지 않는다.

5. **나라장터에 없는 낙찰을 아이건설넷이 아닌 추측으로 채움**
   - 잘못: 96.x에 델타를 더해 99로 밀어 넣음. 5개사 스텁으로 79개사 공고를 덮어씀. 차트는 6칩, 옆 공고는 수십 칩.
   - 규칙: 참여업체 전체 행을 유지한다(`participants.jsonl` / 개찰완료상세). OpenAPI `adjustRate` 96.x는 전장 맵 99.xxxx가 아니다. 1위 아이건설넷 99.xxxx 앵커로 스케일한 뒤 칩을 그린다. 스텁 6개사로 덮지 않는다.

6. **영향진단 수집**
   - 잘못: `국가유산영향진단`을 도메인 토큰에 넣음. 금강 공주 공고가 차트에 뜸.
   - 규칙: 영향진단은 수집·저장·차트 금지. `배수영향구간`은 영향진단이 아니다.

7. **5개사 이하 공고를 올림**
   - 규칙: 고유 업체 6개 미만 공고는 저장·표시하지 않는다.

8. **표준 xlsx를 STORE만 읽음**
   - 잘못: ZIP_STORED·inlineStr만 읽어 실제 엑셀(DEFLATE+sharedStrings)이 실패.
   - 규칙: C++ ingest는 DEFLATE와 sharedStrings를 읽는다.

## 실행·협업

9. **앱을 띄운 뒤 셸 Job이 프로세스를 죽임**
   - 규칙: GUI는 background + Wait-Process. 완료 시마다 Debug exe를 다시 실행한다.

45. **감시 구간을 0.1칸·3개월로 잡고 고정/한번을 안 가름**
   - 잘못: 1위 분포 0.1칸을 대응 위치로 씀. 낙찰은 0.01에서 갈린다. 3개월은 고정 판정 표본이 부족하다. 99.40까지 보면 거의 전 업체가 고정이 된다.
   - 규칙: 홈 99.60–99.70, 감시 바닥 99.50, 기간 1년, 고정은 감시칸 3공고 이상. 대응은 현재 공고 홈 고정 왼쪽 0.01. 업체 색은 유지하고 고정만 왼쪽 막대로 표시. 추천/확률/한점 문구 없음.

44. **1위 %를 범례에 `99.10~99.20 1%` 목록으로 넣음**
   - 잘못: 범례 오른쪽 여백에 구간 문자열을 나열하면 축과 무관하고 잘린다.
   - 규칙: 범례는 동국구간만. 0.1칸(99.10과 99.20 사이) **중앙**에 `%`만. 행 라벨 `1위 (%)`.

43. **1위 0.1칸 %를 축 아래·범례 사용/T점유에 넣고 금테 1위가 둘**
   - 잘못: tick 아래 `50%` + 범례 `사용 lo–hi | T점유 n`. `IsMappedRank1`이 `rank==1`이면 서로 다른 업체도 둘 다 금테.
   - 규칙: 범례 오른쪽 여백에 `99.10~99.20 1%`. 사용/T점유 범례 문구 없음. 축 아래 % 없음. 한 공고 금테 1위는 한 칩(낙찰, 아니면 사정률 낮은 rank1).

42. **1위 분포를 T/사용 한 숫자로 범례에 넣고 0.1칸 축에 안 그림**
   - 잘못: `1위 2% | 사용 1위 0%` 는 분포가 아니다.
   - 규칙: 범례의 그 두 숫자는 지운다. 99–101을 0.1칸으로 나눠 각 칸 % = (그 칸 1위 공고 수)/(1년 99–101 1위 수). 축 아래 여백. 1위 공고가 하나 늘 때마다 재계산.

41. **99–101 1위 낙찰확률을 범례 여백에 안 넣고 공고가 바뀌어도 안 다시 계산함**
   - 잘못: T점유만 있고 1년 1위가 동국구간에 들어온 비율이 없다.
   - 규칙: 범례 여백에 `1위 n%` = (T 안 rank1) / (99–101 rank1, 로드 1년). 공고 개찰일·1위가 바뀌면 `ComputeDonggukBand`가 다시 계산.

40. **업데이트 jsonl이 같은 공고·업체를 두 줄로 넣고 1위가 둘처럼 보임**
   - 잘못: 수집 키워드 6개가 같은 공고를 반복 기록하고, 병합은 DELETE 후 전부 INSERT. sqlite에 낙찰이 두 줄.
   - 규칙: 공고 번호는 한 번만 jsonl에 쓴다. 병합은 CompanyIdentity로 한 줄. UNIQUE(notice_number, company_name). 금테 1위는 공고당 한 칩.

39. **먹이/위협 색으로 업체 칩 고유색을 덮음**
   - 잘못: T 안·왼쪽 칩을 주황/보라로 바꿔 업체 구분이 사라짐.
   - 규칙: 칩은 CompanyColor(동국 빨강). T·사용·위협은 세로 띠만. 1위 낙찰%는 오른쪽 거터에 구간별로.

38. **T를 ‘넣으라’고만 칠하고 타인 점유를 안 그림 / 좁은 집을 사용=T로 연다**
   - 잘못: 사용 구간만 초록으로 칠하고 T 안 타인 점(먹이)을 안 보여 기피가 안 생긴다. iqr<0.15인데 침입이 남은 채로 use=T.
   - 규칙: T=1년 전순위 Q1–Q3를 `동국구간`으로 그리고 T 안 타인은 먹이색. 침입이 남으면 사용은 T 왼쪽 0.05 수비 칸. 기피 중일 때만 use=T. 추천/확률%/사정률 금지.

37. **넣을 구간 색이 드래그(팬) 중에만 보이고 자사집 빨강을 같이 칠함**
   - 잘못: `PaintBandLayer`를 팬 캐시 `PaintScatterWorld`에만 넣고 정지 `PaintChart` 격자 뒤에는 안 넣음. 자사집·경쟁집·부착 채움이 넣을 구간을 가림.
   - 규칙: 정지 프레임과 팬 월드 둘 다 T·사용·위협을 그린다. 범례는 탭 오른쪽·툴바 왼쪽(플롯 밖). 라벨은 `동국구간`/`사용`.

36. **넣을 구간을 1등만·5년 평균·100 오른쪽 미달로 그림**
   - 잘못: rank==1만으로 띠를 만들고, 없는 연도를 상수로 채우고, 자사집 안/오른쪽에 사용 구간을 연다.

35. **한국문화유산연구원과 한국문화재연구원을 한 업체로 합치고, 칩을 앞 2글자라 제주/한국이 겹침**
   - 잘못: `문화유산연구원`→`문화재연구원`이 한울 개명에는 맞지만, 같은 공고에 다른 순위로 들어온 `한국문화유산`/`한국문화재`까지 합침. 칩은 항상 앞 2글자라 `제주문화재연구원`과 `제주고고학연구소`가 둘 다 `제주`.
   - 규칙: `한국문화유산연구원`은 합치지 않는다. 신원은 raw `company_name`을 Canonicalize. 칩/체크박스는 `BuildDisplayMap`으로 업체마다 다른 라벨.

14. **전장 맵 업체명이 칩 밖으로 넘쳐 옆 글자와 붙음**
   - 잘못: 글자 클립을 빼고 글자 크기를 칸보다 크게 그림. `화서`+`미리`가 `화사미리…`처럼 보임.

13. **ProgressBar에 읽기 전용 LoadProgress를 TwoWay로 묶어 시작 크래시**
   - 잘못: `ProgressBar.Value` 기본이 TwoWay인데 `LoadProgress` setter가 private.
   - 규칙: `Value="{Binding LoadProgress, Mode=OneWay}"`. 디자이너가 Mode를 빼지 않게 계약 테스트로 고정.

12. **겹친 칩은 동국을 마지막에 그렸는데 히트테스트는 앞에서 고름**

    - 규칙: 0.1/0.01 같은 칸 히트테스트는 뒤에서 앞으로. 업데이트 후 전장 맵은 표 스냅샷을 복사하고 필터 재조회로 덮지 않는다.

10. **병렬 에이전트가 같은 파일을 덮어 필터를 지움**
    - 규칙: `CollectorNoticeRules` / `rule_profile.json`은 한 작성자만 수정. 끝난 에이전트 결과를 머지하기 전에 현재 파일을 다시 읽는다.

11. **아이건설넷 비밀번호를 소스에 넣음**
    - 규칙: `nara-workspace/app/igunsul.local.env`만. 깃 추적 금지 (`**/igunsul.local.env`).

28. **줌마다 DirectWrite 칩을 다시 그려 전장 맵이 느림**
   - 잘못: 휠 한 칸마다 `ZoomAt` → 전체 칩·글자 재생성. 팬은 BitBlt인데 줌만 풀 리빌드.
   - 규칙: 줌 중에는 마지막 선명한 플롯을 `StretchBlt`. 휠이 멈춘 뒤 `ZoomSettleMs`에 한 번만 다시 그린다.

16. **전장 맵 드래그 후 칩에 업체명이 없음**
   - 잘못: 팬 중에 라벨을 생략한 프레임을 정적 비트맵으로 캐시하고, 호버는 그 비트맵만 BitBlt함. ClearType은 메모리 DC에 글자가 안 남음.
   - 규칙: 라벨을 뺀 드래그 프레임은 캐시하지 않는다. 팬은 라벨이 이미 들어 있는 overscan 플롯 비트맵을 BitBlt한다. DirectWrite 칩을 매 마우스 이동마다 다시 만들지 않는다.

15. **Windows 훅 command에 `${GROK_WORKSPACE_ROOT}`를 넣음**
   - 잘못: `-File "${GROK_WORKSPACE_ROOT}/.grok/hooks/dev-engineering.ps1"` → 변수가 비어 `/.grok/hooks/...`가 되고 PowerShell이 exit 1. 매 프롬프트/툴마다 빨간 글자.
   - 규칙: 훅 command에 `${GROK_WORKSPACE_ROOT}`를 쓰지 않는다. cwd 상대 `.grok\hooks\dev-engineering.ps1` 또는 절대 경로만 `-File`에 넘긴다.

21. **수집 CLI 기본 기간이 2~8월(7개월)인데 표/푸터는 1년**
   - 잘못: `nara_award_collect` argv 기본값이 `2026-02`~`2026-08`. 업데이트 버튼은 12개월을 넘기지만, 인자 없이 돌리면 7개월만 모인다.
   - 규칙: 수집 기본 구간은 `kCollectLookbackMonths`(12). 오늘 기준 같은 달까지. OpenAPI는 3개월 창으로 나눈다. 표·전장 맵도 그 start/end를 쓴다.

22. **한글 사용자 경로에서 sqlite를 ACP `path.string()`으로 열어 빈 표**
   - 잘못: `sqlite3_open`은 UTF-8인데 `PathString`이 `.string()`(ACP)을 넘김. `C:\Users\권을\...`에서 `EnsureParticipantsSchema` 실패, db 없음, 공고 0건.
   - 규칙: sqlite open은 `path.u8string()`/`sqlite3_open16`. 빈 표는 먼저 db/jsonl 존재와 `GetLocalTime` 연도를 나눈다. OS가 2026이면 푸터는 2025-08-28~2026-08-28이다.

23. **「깨끗해 보인다」를 「안 깨끗하다」로 읽고 C#을 고침**
   - 잘못: C#이 깨끗하고 C++가 더럽다는 비교인데, C# 글꼴·그림자를 바꿈.
   - 규칙: UI 불만은 두 앱을 먼저 비교한다. 깨끗한 쪽을 기준으로 더러운 쪽(C++ GDI+)만 고친다.

27. **DirectWrite 칩 글자를 플롯 클립 없이 Flush해서 축·1위 버튼 뒤로 샘**
   - 잘못: GDI+ `ClipPlot` 뒤에 DWrite 큐를 창 전체에 Flush. 외곽 8방향 스트로크가 맵 바깥·Y축·툴바에 보임.
   - 규칙: 칩 라벨은 `clip_plot`. 칩 Flush 후 거터를 다시 채우고 툴바를 그린다. 맵 밖 텍스트는 plot clip 없음.

26. **칩·표 한글을 GDI+ AddString/DrawString으로 그림**
   - 잘못: C# `FormattedText`는 DirectWrite NATURAL_SYMMETRIC+그레이스케일인데 C++는 GDI+ 경로. 150% DPI여도 GDI+ 8px 한글이 뭉개짐.
   - 규칙: 글자는 `dwrite_text`로만. GDI+는 도형. Ideal은 ClearType이 아니다. C#을 바꾸지 않는다.

25. **C#은 DIP×DPI인데 C++는 20을 물리 픽셀로 씀**
   - 잘못: Per-Monitor V2인데 칸·글자·패드를 96dpi 숫자 그대로 그림. 144DPI(150%)에서 C# 칩 30px·한글 12px, C++ 칩 20px·한글 8px. “엔진이 달라서”가 아니라 스케일 누락.
   - 규칙: 레이아웃은 DIP. `GetDpiForWindow/96`로 `ScaleTransform`. 마우스·콤보 HWND만 `DipToPx`. 셀 20은 줌 DIP이지 화면 픽셀이 아니다.

37. **설계원칙을 분석 창 독과 한 화면에 글만 쌓음**
   - 잘못: 설계 탭이 기간·업체 필터 위에 긴 문단만 띄움. 그림이 없거나 맨 아래에 몰림.
   - 규칙: `DesignPrinciplesWindow` 단독 창. 블록마다 왼쪽 그림 280 + 오른쪽 글(제목 1줄, 본문 3~5줄). 그림 없는 문단 금지. 광고 A+B 높이는 원칙 블록 합보다 작고 전체의 1/3을 넘지 않는다. 사정률 입력·추천 점·확률%·최적 산출은 넣지 않는다.

24. **C#처럼 보이게 GDI+ 0.4펜을 글자 위에 그음 / 칩을 둥글게 / 그림자를 하드 오프셋**
   - 잘못: C# `DrawGeometry(white, 0.4 pen)`·`DrawRectangle`·`DropShadowEffect(blur)`를 그대로 GDI+에 옮김. 가는 펜은 ~1px로 번지고, radius 3 칩은 모서리가 흐리며, blur 토큰을 안 쓰고 사각형만 한 장 밑으로 복제함.
