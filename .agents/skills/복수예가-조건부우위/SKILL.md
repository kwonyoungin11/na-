# 복수예가 마스터 스킬

이 스킬은 **복수예가를 예측게임으로 보지 않고, 충돌업체의 왼쪽을 선점하고 내 왼쪽 공간을 확보하는 방식으로 오답을 제거하는 운영체계**로 다룹니다.

## 핵심 명제
- **정답 위치 예측은 불가능하거나 매우 불안정하다.**
- 따라서 목표는 `맞출 자리 찾기`가 아니라 `겹칠 자리 제거하기`다.
- 복수예가에서는 **충돌앵커의 바로 왼쪽**에 서야 상대 우위를 만들 수 있고, **내 왼쪽 공간이 넓어야** 복수예가 형성 흔들림에도 버틸 수 있다.
- 관측된 사정률은 그대로 믿지 않는다. 다음의 합성물로 본다.

```text
관측위치 = 업체의 숨은 의도 + 복수예가 시스템 왜곡 + 군집 압축 + 이산화(0.001 등) 효과
```

## 이 스킬이 보는 4개의 층
1. **시스템 층**
   - 복수예가가 전략공간을 얼마나 좁히는지
   - 낙찰하한/예가 구조 때문에 어디가 본질적으로 압축되는지
2. **전체업체 층**
   - 전체 참여업체가 만들어내는 자연밀도와 초과군집이 어디인지
   - 최근 과열/신규유입이 어디에 생기는지
3. **관계 층**
  - 자사와 전체업체의 거리
  - 자사가 자주 부딪히는 **충돌앵커**가 누구인지
  - 자사가 앵커의 왼쪽에 설 때 확보되는 **좌측여유**가 얼마나 되는지
4. **결정 층**
  - 금지구간 / 경계구간 / **좌측선점 후보밴드**로 나눠서 판단
  - 한 점 추천보다 좁은 밴드 + 앵커 + 좌측여유 설명을 우선

### 결정 층 운영 원칙
- **추천 계산 자체는 경쟁업체-only 지도에서 수행**한다.
- 자사 데이터는
  - 충돌 설명
  - 전술 비교
  - 동국 중심 대비
  에는 쓸 수 있지만,
  **후보밴드 생성 로직의 fixed/density/gap/candidate 계산에는 섞지 않는다.**
- 저장된 JSON 결과는 snapshot일 뿐이므로, **stale 검증 없이 최신 추천처럼 재사용하지 않는다.**

## 언제 이 스킬을 쓰나
- "복수예가에서 예측은 안 된다. 그럼 무엇을 분석해야 하나?"가 핵심 질문일 때
- 전체업체 데이터와 자사 데이터를 **관계 분석**으로 엮어야 할 때
- 반복 충돌업체의 **왼쪽 선점**과 **내 왼쪽 공간 확보**를 전략 중심으로 삼을 때
- 오래된 낙찰다발 구간 대신 **최근 군집/과열/회피 구간** 중심으로 재정의할 때
- 기존 `optimal-position` 류의 정답 찾기 접근을 버리고 **조건부 우위 기반 오답 제거 엔진**을 설계할 때

## 선행 입력
- 정제된 입력은 `/mnt/a/c/.agents/skills/API/rule_profile.json` 규칙을 따른다.
- 경쟁분석 기본값은 `/mnt/a/c/.agents/skills/shadow-strategy/analysis_profile.json` 을 따른다.
- 통합 작업공간 작업이면 `/mnt/a/c/nara-workspace` 산출물을 우선 사용한다.
- C# 언급 없는 요청에서는 데스크톱 경로와 혼합하지 않는다.

## 실행 순서

### 0) 충돌앵커를 먼저 찾는다
먼저 아래를 정리한다.
- 내가 최근 반복해서 부딪히는 업체는 누구인가?
- 그 업체는 오늘도 시장에서 앵커 역할을 할 가능성이 있는가?
- 그 업체 바로 왼쪽에 설 때 내 아래쪽 공간은 얼마나 확보되는가?

### 1) 시스템 해석 먼저
다음 질문을 먼저 고정한다.
- 오늘 공고에서 전략공간이 넓은가 좁은가?
- 참여업체 수가 자연밀도를 얼마나 밀어 올릴까?
- 복수예가 구조상 중심 합의밴드가 강하게 생길 공고인가?

### 2) 전체업체 기준선을 만든다
전체업체를 먼저 본다.
- 자연밀도: 업체 수와 bin 수 대비 원래 겹침이 얼마나 나와야 정상인지
- 초과군집: 자연밀도를 넘어서 유난히 몰린 밴드가 어디인지
- 과열도: 최근 30/90일 기준 신규유입이 어디에 붙는지

단,
- 추천 계산용 지도에서는 자사를 제외하고
- 같은 업체/같은 날/근접 사정률은 먼저 묶는다.

### 3) 자사와 전체업체의 관계를 본다
다음 질문이 핵심이다.
- 자사는 전체 군집의 중심에 자주 들어가는가?
- 자사는 어떤 업체와 반복 충돌하는가?
- 그 반복 충돌업체의 **바로 왼쪽**에 설 수 있는가?
- 그 왼쪽 밴드 아래에 **충분한 좌측여유**가 남는가?
- 자사 습관이 이미 시장에 읽힌 패턴인가?
- 자사가 피해야 할 업체/밴드는 누구/어디인가?

### 4) 결과는 제거형으로 낸다
반드시 아래 형식으로 결론을 낸다.
- **금지구간**: 과열/초과군집/고정점유가 심한 곳
- **경계구간**: 데이터는 있으나 확신이 약한 곳
- **좌측선점 후보밴드**: 충돌앵커의 왼쪽이면서 내 왼쪽 여유가 남는 좁은 밴드
- **불확실성**: 왜 오늘도 확실하다고 말할 수 없는지

추가 원칙:
- 점수만 높은 밴드를 추천하지 않는다.
- **실제 `candidate` semantics + 최소 근거(notice/award evidence)** 를 통과한 밴드만 추천한다.

## 금지 규칙
다음은 이 스킬에서 금지한다.
- 1년 전 낙찰다발 위치를 오늘 추천 근거로 직접 쓰는 것
- 과거 1위 빈도/낙찰빈도만으로 정답점을 찍는 것
- 전체업체를 보지 않고 자사 데이터만으로 위치를 말하는 것
- 한 점을 `정답`이라고 단정하는 것
- 충돌앵커를 보지 않고 단순히 `왼쪽이면 좋다`고 일반화하는 것
- 시스템 왜곡을 무시하고 관측 사정률을 순수 의도로 해석하는 것

## 산출물 형태
최종 결과는 아래 5개를 포함해야 한다.
1. **시스템 해석**: 오늘 공고의 압축도/예측불가성 설명
2. **전체업체 지도**: 자연밀도 vs 초과군집 vs 과열구간
3. **자사-시장 관계 지도**: 자사 충돌패턴, 자사 노출습관, 반복충돌 앵커, 좌측여유폭
4. **제거 목록**: 버려야 할 구간과 이유코드
5. **좌측선점 후보밴드 목록**: 앵커 기준 좁은 밴드, 좌측여유폭, 우선순위, 불확실성 메모

## 기존 스킬과의 관계
- **수집/정제**: `나라장터api수집전처리`
- **경쟁업체 미시 분석**: `shadow-strategy`
- **콘솔 전체 실행**: `logic`
- 이 스킬은 위 도구들을 **상위 해석 프레임**으로 묶고, AI가 매번 같은 설명을 반복해서 듣지 않도록 기본 전제를 고정하는 역할이다.
